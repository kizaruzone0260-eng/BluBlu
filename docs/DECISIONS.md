# Решения по ходу работы

## 2026-10-06 (Фаза 4 — производительность)

- **Ленивая загрузка тяжёлых экранов.** Calendar (FullCalendar), Lesson (LiveKit +
  Excalidraw), Notes/Sheets/MaterialNew (Tiptap + рисование) и ClassDetail (тянет
  RichText через ленту) переведены на `React.lazy` + `<Suspense>`. Entry-чанк упал
  с 2 870 kB до 998 kB (gzip 876→282). Новые зависимости ради этого НЕ добавляны.
- **`@fastify/compress` (MIT)** — единственная новая рантайм-зависимость фазы, только
  на сервере (в браузер не попадает). `encodings:['br','gzip']`, `threshold:0`,
  `ifContentEncoding:'identity'`. Не сжимает медиа/PDF (не в списке compressible),
  поэтому byte-range отдача файлов не затронута (проверено правами/файловыми тестами).
- **Кэш-стратегия статики (onSend в `app.ts`):** `/assets/*` (контент-хэш Vite) →
  `immutable, max-age=1y`; HTML-shell и `sw.js` → `no-cache` (revalidate по etag),
  чтобы новый деплой подхватывался сразу. Приватный API остаётся `no-store`.
- **Lighthouse/CWV не запускались** в этом окружении (нет headless Chrome Lighthouse);
  зафиксированы точные byte-size до/после и расщепление на async-чанки как измеримое
  доказательство. Полный Lighthouse-прогон — в «не проверено без реального окружения».
- **Холодный старт Render free tier** осознанно НЕ чинится (по заданию) — только отмечено.

## 2026-10-06 (Фаза 2 — согласия)

- **Единый гейт согласия вместо отдельного экрана для ролей.** `policy_acceptances`
  хранит одну строку `(userId, version, acceptedAt)`. `/api/me` отдаёт
  `policyAccepted = storedVersion === POLICY_VERSION`. SPA показывает экран
  принятия, пока это `false` — тем же механизмом покрываются и «первый вход
  учителя», и «существующие пользователи после смены версии». Регистрация ученика
  добавляет чекбокс на шаге 2 (без него submit блокируется), и после создания
  аккаунта вызывает `accept-policy`, поэтому ученик не упирается в гейт.
- **Смена версии ⇒ одно повторное принятие.** `POLICY_VERSION` (`2026-10-06`) в
  `packages/shared`. Поднять её вместе с текстами — и все примут заново при
  следующем входе. Миграций при этом не нужно.
- **Юридические тексты — черновики.** Описывают фактический стек (Render/Supabase
  Frankfurt, LiveKit Cloud для демо, Telegram, youtube-nocookie по клику). Поле
  контакта и блок несовершеннолетних — осмысленные плейсхолдеры `[…]` (НЕ пустые
  строки: тест паритета запрещает пустые значения). Правовую проверку делает владелец.
- **Тексты в локалях как массивы секций** (`privacy.sections`, `terms.sections`),
  одинаковая структура в ru/uz/en; паритетный тест рекурсивен по массивам —
  количество секций/абзацев обязано совпадать.
- **e2e-фикстуры сеют принятие** (`e2e-stack.mjs`), иначе каждая спека упиралась
  бы в гейт; спеки регистрации ставят `reg-consent`. `zz5-policy` проверяет
  и чекбокс, и пост-логин гейт на свежем аккаунте.

## 2026-10-06 (Фаза 1 — защита)

- **Callback-ключ бота отделён от JWT_SECRET (HKDF).** Подпись `callback_data`
  теперь идёт от отдельного ключа, выведенного HKDF-SHA256 из `JWT_SECRET`
  (info `klass.cb.v2`). Новые кнопки — версия `c2`; старые `c1` (HMAC по
  `JWT_SECRET`) ВЕРИФИЦИРУЮТСЯ по-прежнему, так что уже отрисованные в чате
  кнопки не ломаются — миграция подписи без переустановки кнопок. Доказательство:
  `phase1-hardening` («JWT-signed c2 refused», «legacy c1 verifies», round-trip).
- **Spike-комната LiveKit отключена в production.** Диагностический
  `/api/rtc/token` выдавал 6h publish-токен на любую `spike-*` комнату; в
  `NODE_ENV=production` возвращает 404. В dev/test/e2e остаётся рабочим
  (используется страницей `/spike` и тестом прав). TTL токена урока 6h→3h,
  spike 6h→1h, хвост имени комнаты 4→8 байт.
- **Политика пароля ≥10 + denylist частых** применяется ПРИ СОЗДАНИИ (регистрация,
  установка временного). Вход ослаблен до непустой строки — иначе аккаунты,
  созданные под старым минимумом 8, не смогли бы войти. Сервер возвращает
  переводимый код (`passwordTooShort/TooSimple/TooCommon`), сообщение на ru/uz/en.
- **`style-src 'unsafe-inline'` в CSP оставлен.** Без него Excalidraw не рендерит
  инлайн-стили холста. `script-src` остаётся `'self'` (без unsafe-inline/unsafe-eval),
  `frame-src` — только self/blob/youtube-nocookie. Принятый риск задокументирован.
- **`braces` high из `pnpm audit --prod`.** Транзитив через
  `@excalidraw/excalidraw → sass → chokidar → braces`; это BUILD-time зависимости
  (не исполняются на сервере и не попадают в раннер браузера отдельно от самой
  доски), апстрим-патча нет (`Patched <0.0.0`). Принято как документированный
  риск; CI оставлен `continue-on-error` с явным списком. `katex` low — тот же
  mermaid-поддерево.
- **Локаут перебора по аккаунту НЕ реализован** (в «Требует решения»). Пер-IP
  лимит входа 10/мин сохранён и усилен (в prod env-ослабления игнорируются).
  Полноценный email-лок конфликтует с существующим trustProxy-тестом и в
  одно-инстансной модели избыточен; предложение — таблица `login_failures`
  (см. HARDENING.md п. 1д-3).

## 2026-10-04 (облачный деплой: Render + Supabase)

- **Grace-окно переиспользования refresh-токена (REFRESH_REUSE_GRACE_MS, по
  умолчанию 5 с, максимум 30 с):** браузер, отменивший запрос ротации
  (мгновенный reload во время бутстрапа), повторяет «съеденный» токен — раньше
  это считалось кражей и убивало family (нестабильность входа). Теперь повтор
  в пределах окна и при нетронутом преемнике молча выдаёт новую сессию;
  поздний повтор по-прежнему убивает family (тест с grace=0 сохраняет строгое
  поведение §4).
- **Supabase Data API закрывается скриптом db:secure** (RLS на все таблицы
  public + REVOKE anon/authenticated + default privileges), а не миграцией
  drizzle — приложение ходит в Postgres напрямую; владелец таблиц `postgres`
  RLS обходит по определению.
- **Render free:** постоянного диска нет → STORAGE_DIR=/tmp (файлы живут до
  перезапуска; для прода — volume/S3-совместимый провайдер), health-check
  GET /api/health без версий/секретов, WS-клиенты переподключаются с новым
  одноразовым билетом (backoff до 10 с).
- **Видеозвонок в облаке: refresh-403 как первопричина.** Live-воспроизведение
  на Render показало: при любой перезагрузке страницы POST /api/auth/refresh
  отвечает 403, потому что checkSameOrigin сверял Origin только со статическим
  списком из env (PUBLIC_WEB_ORIGIN/DOMAIN/PUBLIC_URL), а PUBLIC_URL на первом
  деплое пуст → сессия не восстанавливается, /lesson открывает логин. Правка:
  Origin разрешается и когда его host совпадает с заголовком Host запроса
  (CSRF-safe: скрипты не могут подставлять Host). Плюс CSP: connect-src больше
  не содержит голых ws:/wss: — только 'self', blob: и origin LiveKit из
  LIVEKIT_URL/LIVEKIT_WS_URL; inline-регистрация service worker вынесена в
  main.tsx и отключён vite modulePreload-полифилл, чтобы script-src 'self'
  не нарушался. Тесты: same-Host refresh (Render-сценарий) и CSP-директивы.
- **Рисование в заметках — собственный лёгкий SVG-инк, не Excalidraw.**
  Excalidraw в сборке есть (доска урока, ленивая загрузка), но встраивать его в
  каждую заметку дорого по памяти (Render free = 512 МБ) и его scene-JSON
  не тривиально инлайнить в HTML тела заметки. Реализация: Pointer Events
  (мышь/тач/стилус), режим рисования in/out (выключен → touch-action:auto,
  страница скроллится пальцем как обычно), штрихи [{c,w,e?,pts}] хранятся
  одной строкой в атрибуте data-note-drawing (encodeURIComponent JSON) внутри
  body заметки → автосейв/эмоpty-правило (§2: штрих = содержимое)/просмотр
  работают без новых колонок и API. Лимит 500 КБ на код (понятная ошибка).
  Права доступа не менялись.
- **Камера в уроке: плитки — React-состояние, а не императивная вставка в DOM.**
  Живое repro на Render (Playwright, фейковая камера, учитель+ученик) показало:
  демонстрация экрана видна, а видео с камеры — ни у кого. Причина: плитки
  создавались в RoomEvent.LocalTrackPublished/TrackSubscribed и вставлялись в
  сетку через put(), которая выходила без if (!gridRef.current) return — а сетка
  рендерится только после setConnected(true), т.е. ПОСЛЕ connect()+включения
  треков. Все треки, опубликованные/подписанные до этой минуты (своя камера и
  всё, что уже было в комнате), терялись молча; экранируется только то, что
  включается позже (демо экрана) — отсюда «экран работает, камера нет». Тот же
  гонка объясняла эхо: локальный <audio> не имел muted и при удачном попадании
  в сетку начинал играть пользователю его же микрофон. Правки: tiles в useState
  (+ Map треков в ref, attach/detach в useEffect) — порядок событий больше не
  важен; локальный звук не подключается ни к какому элементу; удалённый audio
  скрыт из сетки (display:none). Камера включается цепочкой МЯГКИХ ограничений
  (идеальные 1280×720@30 → дефолтное устройство → video:true) с сохранённым
  выбором устройства и понятными ru/uz/en ошибками (denied/busy/not found) —
  молчаливый отказ убран; кнопки микрофона/камеры отражают реальное состояние
  публикаций LiveKit; добавлены пики устройств и живое предпросмотр-видео до
  входа. Заголовки: Permissions-Policy camera/microphone/display-capture=(self)
  (helmet v8 выкинул этот middleware — ставим хуком) и CSP connect-src теперь
  содержит и https://host LiveKit (клиент ходит туда за /settings/regions —
  раньше каждый вход в урок логировал CSP-нарушение); шрифты Excalidraw
  самохостятся (build копирует dist/prod/fonts в public/, window.
  EXCALIDRAW_ASSET_PATH='/excalidraw-assets') — font-src CSP больше не режет
  esm.sh. Тесты: unit (цепочка ограничений/маппинг ошибок), интеграционный
  (CSP+Permissions-Policy), e2e zz-camera.spec.ts (реальный RTC с фейковой
  камерой: у второго участника появляется <video> с ненулевыми размерами,
  локальный <audio> отсутствует; в CI без LIVEKIT_* skip с причиной).

- **Модерация урока — понятная обратная связь (task 3).** «Выключить всем

  (chip-active) и меняют подпись («Включить микрофоны всем», «Режим лекции:

- **Telegram-бот: состояния диалогов — в Postgres, callback-и — подписаны.**
  Render-сервис спит между запросами, поэтому шаг /announce и /contact живёт
  в bot_sessions (chat id, state, data, expires_at) вместо памяти, а
  повторная доставка update_id отсекается журналом bot_updates (вебхук всегда
  отвечает 200 и не падает на холодном старте). callback_data = base64url

  сервере) — подделанная или чужая кнопка даёт «устарела или не для вас» без
  каких-либо данных. Роль берётся из telegram_links→users.role и
  проверяется на каждой команде; в группах бот молчит (кроме прежнего
  /link). Отправка объявления claimed-операцией (UPDATE…WHERE state=
  'announce:confirm' после чтения сессии): повторное нажатие не создаёт
  дубль. /contact: отчёт одному учителю (учитель класса при однозначном

  блок-лист; весь пользовательский текст экранируется (parse_mode HTML).
  Публичное расписание по названию — только при classes.bot_public_schedule
  (по умолчанию выключено), ответ одинаков для «нет такого» и «закрыто»,
