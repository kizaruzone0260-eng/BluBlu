# Библиотека материалов Telegram-помощника

Учебник загружается **один раз** и прикладывается к заданиям снова. Это переиспользуемое
вложение, а не сохранённый текст: файл живёт в Telegram, в базе — только его `file_id`,
записанный тип носителя, координаты исходного сообщения и название, которое набрала
преподавательница.

Главный принцип: **ИИ не читает содержимое файлов.** Модель видит написанные учителем
тексты и названия материалов. PDF-парсеров, DOCX-извлекателей, OCR и vision в этом
модуле нет, и включить их одной переменной нельзя.

## Как попасть

- команда `/library` в личном чате с ботом (пункт меню учителя
  «📚 Библиотека материалов»; у английского аккаунта меню по-английски — `Material library`);
- кнопка «📚 Библиотека материалов» на единственном экране сбора в `/homework`; с предпросмотра
  туда же ведёт «Добавить материалы»;
- «➕ Загрузить новый материал» на экране выбора сохранённых книг — учебник можно оформить,
  не выходя из задания.

`/materials` не тронута: она по-прежнему показывает материалы классов BluBlu. Все операции
библиотеки доступны только привязанной учительнице; чужой `material_id` для неё просто не
существует.

## Меню библиотеки

| Действие | Что делает |
|---|---|
| ➕ Добавить материал | Выберите группу, пришлите файл, задайте название и тип, подтвердите |
| 📝 Выбрать материал для ДЗ | Открывает `/homework`: книга отмечается на экране сбора кнопкой «📚 Библиотека материалов» |
| 📂 Материалы моих групп | Список групп со счётчиком активных материалов, дальше — список группы |
| ⚙️ Управление материалами | Все материалы, фильтр по группе, переименование, подключение к другой группе, архив, удаление |

## Добавление материала

1. «Добавить материал» → отметить группу или группы (отметку можно снять).
2. Прислать файл одним сообщением: PDF, DOCX, другой документ или фото. Предел — 20 МБ.
   Подпись под файлом используется как предложенное название.
3. Название. По умолчанию предлагается имя файла без расширения; если Telegram не дал имени
   (фото), предлагается честная заготовка вида `Фото 2026-10-22`. Название редактируется
   всегда, предел — 140 символов.
4. Тип: 📕 Книга, 📗 Рабочая тетрадь, 📄 Другой материал.
5. Экран проверки: название, тип, файл, группы. Кнопка «💾 Сохранить в библиотеку».

При сохранении записываются не только `file_id`, но и **тип носителя** (`photo` / `document`) и
координаты исходного сообщения (`source_chat_id`, `source_message_id`) — именно оттуда
публикация будет копировать файл. Тип берётся из того, как сообщение пришло в Telegram, а не из
MIME: PNG, отправленный «как файл», так и останется документом.

Во время добавления в учебные группы **не уходит ничего** — это склад, а не рассылка.
`/cancel` отменяет шаг, библиотека не меняется; прерванный диалог не оставляет записей.

Тот же файл второй раз не создаёт дубль: запись обновляется (название, тип, `file_id`,
`media_type`, координаты исходного сообщения, группы). Одинаковые названия у разных файлов
остаются разными материалами — бот различает их по `file_unique_id`.

## Рекомендации зависят от группы

- экран «📚 Библиотека материалов» в задании предлагает только активные материалы, подключённые
  **ко всем** выбранным группам: если в задании две группы, книга из одной из них не будет
  отправлена второй;
- порядок — недавно использованные первыми, затем по дате добавления; никакой AI-_ranking;
- если подходящих материалов нет, бот говорит «Для выбранных групп сохранённых материалов нет»
  и предлагает загрузить новый или вернуться к заданию — выбор книги не обязателен;
- «➕ Использовать в другой группе» добавляет связь с подтверждением, файл повторно не
  загружается.

## Как выглядит задание

Отдельного вопроса «что нужно выполнить?» в потоке больше нет. Отметили книгу — остались на том
же экране сбора и написали `Unit 2, Exercises 1–5` обычным сообщением: это текстовый материал
черновика, и форматтер кладёт его в текст задания. `tg_drafts.instruction` бот не заполняет;
экран предпросмотра печатает строку «Инструкция: …» только для черновиков, созданных предыдущей
версией.

Предпросмотр явно показывает:

```
Предпросмотр задания для групп (1):
Кому: IELTS B2
Материалы: English Grammar in Use
📎 «IELTS B2» — 📕 Книга: English Grammar in Use
—
<текст задания>
```

Локальный форматтер (`AI_PROVIDER=none`) собирает сообщение из заголовка, материалов и
присланных сообщений на языке учительницы, ничего не перефразируя. Внешняя модель получает тот
же набор: тексты, названия и имена файлов — и обязана вернуть строгий JSON. Дедлайны, номера
страниц и упражнения, которых учительница не написала, в тексте появляются только как
предупреждение «проверьте эти числа».

## Как уходят вложения

Публикация не пересылает файл заново, а **копирует исходное сообщение** учительницы:
`copyMessage` для одного файла и `copyMessages` для альбома — сообщения с одним
`media_group_id` копируются одним вызовом и приходят в группу альбомом. Поэтому повторное
использование книги — это копирование того же сообщения, без загрузки и без повторной отправки
байтов, а фото остаётся фото и файл остаётся файлом со своим именем и подписью.

`file_id` — только запасной путь: он используется, когда координат исходного сообщения нет или
Telegram отверг копирование ошибкой 4xx, и отправляется с записанным типом (фото →
`sendPhoto`, документ → `sendDocument`). Угадать метод по MIME нельзя: PNG, присланный «как
файл», живёт в `message.document`, и `sendPhoto` отвергает его ошибкой «400 can't use file of
type Document as Photo» — этот отказ и был причиной сбоя в бою.

Итог пишется по каждой части: `tg_publications.parts` — текст и каждое вложение с методом
(`copy` / `file_id` / `text`) и статусом (`sent` / `failed` / `unknown`). Экран результата
говорит `✓ <группа> — отправлено` или `⚠ <группа> — доставлено N, не доставлено M` и перечисляет
части построчно, а не считает группы: «отправлено 0 из 1» для задания, чей текст уже лежит в
группе, — неправда.

## Экран «📚 Библиотека материалов»

Открывается одной кнопкой с экрана сбора и возвращается туда же по «✅ К заданию (n)»; с экрана
предпросмотра туда попадают через кнопку «Добавить материалы», которая возвращает на экран
сбора. Книги можно отметить или снять, загрузить новую прямо посреди задания, вернуться к
черновику или отменить его. Если после предпросмотра группы меняются, материалы, которые не
относятся к новому набору, убираются из черновика с явным сообщением — полуотправленного
задания не бывает.

## Управление, архив и удаление

- **Переименовать** — меняет только будущие рекомендации. Черновики и история отправок
  сохраняют название, под которым материал был выбран.
- **Убрать из рекомендаций** — статус `archived`. Материал больше не предлагается новым
  заданиям, но остаётся в библиотеке и его можно вернуть.
- **Удалить из библиотеки** — с явным подтверждением. Удаляется запись библиотеки и связи
  с группами; снапшот в черновике сохраняется (`material_id` → NULL), истории отправок и
  сообщения в Telegram не касаются. Отправленные задания не удаляются никогда.
- Снятый с рекомендаций или удалённый материал не может остаться активной рекомендацией:
  все списки строятся по статусу и владельцу на момент показа.

## Надёжность хранения

Для MVP материал живёт в Telegram — на его `file_id` и на координатах исходного сообщения:

- байты не хранятся ни в базе, ни на диске (важно для эфемерного диска Render);
- файлы не отправляются AI-провайдеру;
- публикация работает с исходным сообщением: `copyMessage` переотправляет то, что Telegram уже
  имеет, а `file_id` пробует только как запасной вариант — и с записанным типом носителя;
  отдельной проверки `getFile` перед публикацией больше нет, она не нужна, когда содержимое
  никто не скачивает;
- если Telegram явно отказал по этой части (4xx), она помечается `failed`, показывается в
  отчёте по имени файла с причиной и попадает в «Повторить неудачные»; если ответ не пришёл
  вообще — `unknown`, и эта часть не повторяется никогда;
- если обрыв произошёл уже после доставленной части, строка помечается `uncertain`, а черновик
  — `publish_unknown`; повторной кнопкой такая строка не предлагается — иначе группа получила
  бы задание дважды, — и `/homework` не открывается её отчётом;
- запись библиотеки при неудачной отправке не меняется: пропажа исходного сообщения или
  отказ `file_id` — это повторная загрузка файла, а не потеря данных.

`file_id` **не является** гарантией бессрочного хранения оригинала: он привязан к аккаунту
бота и к политике Telegram. Отдельное постоянное хранилище книг (S3/R2/свой диск) —
следующее направление, оно не подключено и не должно включаться без согласования.

## Переменные окружения

Библиотека не вводит новых переменных. Работают те же, что и для помощника:
`TELEGRAM_BOT_TOKEN`, `TELEGRAM_TRANSPORT`, `TELEGRAM_MODE`, `AI_PROVIDER`, `AI_BASE_URL`,
`AI_API_KEY`, `AI_MODEL`, `AI_TIMEOUT_MS`. Настройки `AI_VISION` и `AI_MAX_IMAGES` удалены:
метод, который мог бы отдать модели содержимое файла, из транспорта убран.

## Инструкция для живой проверки в Telegram

Выполняется только при наличии тестового бота и тестовой группы. **Не** в рабочих группах
с учениками.

### Состояние на 2026-10-22

Живая проверка **не выполнена**: `TELEGRAM_BOT_TOKEN` в `%USERPROFILE%\blublu-secrets\cloud.env`
— пустая строка, AI-ключа в окружении нет. Это подтвердил штатный read-only инструмент
`pnpm --filter @klass/api exec tsx scripts/bot-status.mjs -- --env <cloud.env>`, который
ответил: «no bot token … the value in the file was empty». Никаких значений он не печатает.
Локальный запуск API (`/api/health` → 200, миграции применяются при старте, лог без секретов)
проверен и проходит; поведение помощника проверено на захватывающем транспорте и локальном
OpenAI-совместимом стабе, включая настоящий маршрут `POST /webhook/telegram`
(`test/integration/homework-webhook.test.ts`).

### Как запустить, когда появится тестовый бот

Тестовый бот обязателен: рабочий `@blublu_bot` не трогают — у него вебхук указывает на
deployment, и локальный запуск с тем же токеном либо перехватит обновления прода, либо упадёт
с 409 (polling при установленном вебхуке запрещён).

1. `@BotFather` → новый бот; токен — в локальный файл вне репозитория (например
   `%USERPROFILE%\blublu-secrets\test-bot.env`), не в git.
2. Две тестовые группы **без учеников**, бот в обеих — администратор.
3. Локальный запуск в режиме polling, чтобы не трогать никакого вебхука:

   ```bash
   # PowerShell, значения подставляются из файла, не печатаются в историю
   $env:NODE_ENV='development'
   $env:DATABASE_URL='postgres://klass:klass@127.0.0.1:5433/klass'   # своя тестовая база
   $env:JWT_SECRET=(Get-Content ..\..\secrets\local-jwt.txt)
   $env:TELEGRAM_BOT_TOKEN=(Get-Content ..\..\secrets\test-bot-token.txt)
   $env:TELEGRAM_TRANSPORT='telegram'
   $env:TELEGRAM_MODE='polling'
   $env:AI_PROVIDER='none'          # живой AI-ключ не обязателен для первых 10 шагов
   pnpm --filter @klass/api dev
   ```

4. Проверка конфигурации без отправки сообщений: `pnpm --filter @klass/api exec tsx
   scripts/bot-status.mjs -- --env <путь к test-bot.env>` — только `getMe`,
   `getWebhookInfo`, `getMyCommands`.
5. Дальше — чеклист ниже. Он повторяет сценарий §4 этапного задания, по одному шагу на экран.

### Чеклист живой проверки

1. В личном чате: `/homework` → «➕ Подключить группу» → в группе `/bind КОД`.
   Ожидание: подтверждение в группе и в личном чате, группа появилась в списке. Ответ в группе
   на английском: он уходит до того, как стал известен язык владельца.
2. Английскому аккаунту открыть список `/`-команд в этом чате. Ожидание: все подписи
   английские (`Homework to Telegram`, `Material library`) при любом языке клиента; в русской
   или узбекской программе — никаких русских подписей рядом с английскими экранами.
3. `/library` → «Добавить материал» → отметить группу → отправить PDF учебника →
   название → тип «Книга» → «Сохранить». Ожидание: сообщение о сохранении; **в группу не
   ушло ничего**.
4. `/homework` → та же группа → «✅ Продолжить (1)». Ожидание: один экран сбора с ровно тремя
   кнопками — «Готово — подготовить задание», «📚 Библиотека материалов», «Отмена» — и без
   промежуточных шагов «использовать сохранённый материал» и «что нужно выполнить».
5. «📚 Библиотека материалов» → отметить книгу → «✅ К заданию (1)». Ожидание: тот же экран
   сбора, где появилась строка «Выбрано из библиотеки: …». Набрать `Unit 2, Exercises 1–5` и
   отправить. Ожидание: «✓ Получено — N», и в учебной группе по-прежнему ничего не появилось.
6. «Готово — подготовить задание». Ожидание: одна короткая строка «Готовлю задание…» и
   предпросмотр с блоками «Материалы» и `📎 «группа» — …`; её слова про `Unit 2` видны в тексте
   задания; отдельного вопроса про инструкцию нет. Пугающих предупреждений на экране нет.
7. «Опубликовать в группы» один раз. Ожидание: в группе сначала текст задания, затем файл
   учебника, **скопированный из её же сообщения**; в личном чате `✓ <группа> — отправлено` и
   «Готово: задание опубликовано во все выбранные группы»; у материала появилась дата последнего
   использования. В консоли API — вызов `copyMessage`, а не `sendDocument`.
8. Повторно нажать ту же кнопку «Опубликовать» (или быстро нажать дважды). Ожидание: «кнопка
   устарела или не для вас» (токен кнопки одноразовый) либо «этот черновик уже отправляется или
   отправлен — повторной отправки не будет»; в группе — ровно один набор сообщений.
9. PNG, отправленный «как файл» (документом). Ожидание: в группу он приходит тем же
   сообщением-документом, без «can't use file of type Document as Photo». Несколько фото,
   отправленных альбомом, должны прийти в группу одним альбомом — одним `copyMessages`.
10. Новое задание в той же группе: книга предлагается сразу, без повторной загрузки.
    Написать `Unit 2`, опубликовать. Ожидание: новый текст, тот же файл снова копией исходного
    сообщения — байты не загружаются заново.
11. `/homework` после неудачной или неизвестной отправки. Ожидание: новый `/homework` открывает
    выбор групп, а не отчёт прошлой публикации; прошлый отчёт — в «История отправок».
12. `/library` → «Управление материалами» → переименовать книгу → убедиться, что старые
    отправки в истории остались под прежним названием.
13. «Убрать из рекомендаций» → создать новое задание: книги нет в списке. «Вернуть в
    рекомендации» → книга снова есть.
14. «Удалить из библиотеки» → история предыдущих отправок не изменилась.
15. Отрицательные проверки: не-администратор в группе и `/bind`; ученик и `/library`;
    отправка текста вместо файла; файл больше 20 МБ.
16. Ошибка отправки и сохранение черновика: опубликовать в две группы, из второй бота удалили.
    Ожидание: по живой группе — `✓ … — отправлено`, по сбойной — `✗ … — ошибка: …`, кнопка
    «Повторить неудачные» есть, черновик и материалы целы. Если часть не дошла, а текст дошёл —
    заголовок `⚠ <группа> — доставлено N, не доставлено M` и построчный список частей
    («• текст — отправлено», «• file.png — не отправлено: <причина>») плюс подсказка прислать
    файл заново. Повтор доотправляет только отказавшую часть: текст в группу второй раз не уходит.
    Если после первой доставленной части связь оборвалась, статус — «? … — статус доставки
    неизвестен; проверьте группу», и кнопка повтора НЕ показывается: это защита от дубля, а
    не отказ.
17. Проверка недоступного файла: живой `file_id` и живое исходное сообщение не испортить,
    поэтому случай закрыт тестами `falls back to the stored file_id with the RIGHT type when the
    source message is gone` и `reports a refused file as that file, with the text still credited
    as delivered`; в Telegram он выглядел бы как строка «• <файл> — не отправлено: <причина>» и
    просьба прислать файл заново.
18. Если задан `AI_PROVIDER=openai-compatible`: убедиться, что в тексте задания нет
    номеров страниц, дней недели и дедлайнов, которых не было во введённых сообщениях
    (такие случаи помечаются предупреждением); при `none` — что текст собран только из
    присланных текстов и названий материалов.

## Что автоматическими тестами не подтверждается

- реальные ответы Telegram Bot API (поведение `copyMessage`/`copyMessages`, лимиты
  `sendDocument` и `sendPhoto` по `file_id`, ответы `setMyCommands` в scope чата, поведение
  webhook);
- ответы настоящей AI-модели;
- поведение в живых группах учеников;
- восстановление `file_id` и живость исходного сообщения после долгого простоя бота.

Автоматические тесты используют `CapturingApi` и `FakeAi`: они доказывают правила продукта,
но не заменяют живую проверку из раздела выше.
