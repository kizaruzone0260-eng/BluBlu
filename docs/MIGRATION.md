# Перенос на другой VPS за час

Прямое требование ТЗ (§8 «Переносимость»). Система спроектирована переносимой:
один репозиторий, один compose-файл, никаких провайдер-специфичных сервисов.

## Шаг 0 (заранее, на старом сервере)

Бэкап актуальным (`deploy/scripts/backup.sh`) и копирование архивов на переносимый
носитель/другую машину:

```bash
scp server1:/var/lib/klass-backup/klass-<stamp>.* server2:/var/lib/klass-backup/
```

## Шаг 1 (новый сервер)

```bash
curl -fsSL https://get.docker.com | sh
git clone <репозиторий> klass
cp .env server-backup.env   # тот же .env переносим с собой (секреты вне гита)
```

Домен: сменить A-запись на новый IP (DuckDNS — одной ссылкой; свой регистратор —
у себя). Если IP меняется надолго, проверить, что бэкапы/мониторинг настроены на
новый адрес.

## Шаг 2 — данные

```bash
cd klass/deploy
docker compose up -d postgres
BACKUP=/var/lib/klass-backup/klass-<stamp>.sql.gz \
FILES_BACKUP=/var/lib/klass-backup/klass-files-<stamp>.tar.gz.enc \
BACKUP_PASSPHRASE=... bash scripts/restore.sh
docker compose up -d --build
docker compose ps    # healthy; api сам применяет миграции и поднимет webhook бота
```

Готово: ≤ 20 минут реальных действий. Ничего не меняется в самой системе при смене
провайдера — отличается только пункт «порты в панели облака»: 80, 443 TCP; 7881 TCP;
7882 UDP; 3478 UDP; 5349 TCP.

## Если сервер потерян целиком без бэкапов

Аккаунты/классы воссоздаются вручную; коды приглашений учитель генерирует новые.
Файлы без бэкапа не восстановить — поэтому копия вне сервера обязательна (README).

## Oracle-специфика (почему может понадобиться перенос)

- Oracle останавливает простаивающие Always Free инстансы; при остановке достаточно
  перезапустить инстанс в консоли и `docker compose up -d` (данные на volume переживают
  перезагрузку).
- При удалении инстанса/аккаунта — перенос по шагам 1–2 выше.
