# Данные владельца для политики и условий (аудит SEC-01)

Этот файл — список фактов, которые может дать **только владелец экземпляра BluBlu**.
Разработка не заполняет их догадками: неверный оператор, адрес или порядок согласия
родителей хуже, чем видимый плейсхолдер. Юридическую проверку текстов выполняет владелец;
здесь нет юридической консультации и нет заявления о соответствии какому-либо закону.

Тексты опубликованы как есть (`/privacy`, `/terms`) и принимаются через гейт согласия.
Пока пункты ниже не заполнены, в тексте остаются плейсхолдеры — это известное ограничение,
а не забывчивость (см. `docs/DECISIONS.md`, 2026-10-28).

## Чего здесь намеренно нет

- имён, адресов, e-mail и должностей владельца;
- возрастного порога и процедуры согласия родителей;
- утверждений о соответствии GDPR/иному закону;
- обещаний сроков, которых код не обеспечивает.

## Порядок после заполнения

1. Внести факты в **три** языка одинаковым числом пунктов: `locale-keys.test.ts` требует
   идентичного дерева ключей, включая длину массивов.
2. Поднять `POLICY_VERSION` в `packages/shared/src/constants.ts` (сейчас `2026-10-28`) и
   продублировать дату в `privacy.version` и `terms.version` всех трёх локалей.
3. Пересобрать `@klass/shared` (`pnpm --filter @klass/shared build`) — API читает `dist`.
4. Прогнать `privacy-attendance.test.ts`, `locale-keys.test.ts`, `phase2-consent.test.ts`.
5. Повторное согласие произойдёт автоматически при следующем входе: сохранённая строка
   `policy_acceptances` под прежней версией перестаёт считаться принятой и заменяется одной
   новой (`/api/me` → `policyAccepted=false`). Это доказано интеграционным тестом.
