# Данные владельца для политики и условий (аудит SEC-01)

Этот файл — список фактов, которые может дать **только владелец экземпляра BluBlu**.
Разработка не заполняет их догадками: неверный оператор, адрес или порядок согласия
родителей хуже, чем видимый плейсхолдер. Юридическую проверку текстов выполняет владелец;
здесь нет юридической консультации и нет заявления о соответствии какому-либо закону.

Тексты опубликованы как есть (`/privacy`, `/terms`) и принимаются через гейт согласия на
сайте, в боте и в Telegram Mini App. Пока пункты ниже не заполнены, в тексте остаются
плейсхолдеры — это известное ограничение, а не забывчивость (см. `docs/DECISIONS.md`,
2026-10-28). **SEC-01 не считается закрытым, пока эти факты не внесены и тексты не проверены
юристом владельца.**

## Что код уже делает (факты для текста, не для догадок)

- Принятие фиксируется на сервере в `policy_acceptances`: `user_id`, `version` (legacy),
  `privacy_version`, `terms_version`, `locale`, `context` (`web`/`bot`/`mini`), `accepted_at`.
  Одна строка на пользователя; повторное принятие обновляет её, а не создаёт дубликат.
- Гейт проверяется сервером при каждом действии в боте и Mini App; прямые URL и старые
  кнопки не обходят его. Смена версии документов требует повторного принятия.
- Mini App не хранит согласие в localStorage; там только ограниченный токен сессии
  (sessionStorage), выбранная тема и язык.
- Загруженный файл проверяется по содержимому (magic bytes), а не по расширению; опасные
  типы (HTML, SVG, исполняемые файлы) отклоняются. Файл отправляется боту в личный чат,
  чтобы получить `file_id`, и хранится в `STORAGE_DIR` экземпляра.
- Внешний AI получает только текст задания, адреса ссылок и имена файлов; содержимое файлов
  не отправляется. Результат AI — черновик, который учитель подтверждает перед отправкой.
- При удалении аккаунта записи Mini App, привязки, коды и файлы из `STORAGE_DIR` удаляются
  (см. `services/account.ts`).

## Чего здесь намеренно нет

- имён, адресов, e-mail и должностей владельца;
- возрастного порога и процедуры согласия родителей;
- утверждений о соответствии GDPR/иному закону;
- обещаний сроков, которых код не обеспечивает;
- утверждения, что файлы «хранятся вечно» или «удаляются навсегда» сверх того, что делает код.

## Порядок после заполнения

1. Внести факты в **три** языка одинаковым числом пунктов: `locale-keys.test.ts` требует
   идентичного дерева ключей, включая длину массивов.
2. Поднять `POLICY_VERSION` в `packages/shared/src/constants.ts` (сейчас `2026-10-29`) и
   продублировать дату в `privacy.version` и `terms.version` всех трёх локалей.
3. Пересобрать `@klass/shared` (`pnpm --filter @klass/shared build`) — API читает `dist`.
4. Прогнать `privacy-attendance.test.ts`, `locale-keys.test.ts`, `phase2-consent.test.ts`.
5. Повторное согласие произойдёт автоматически при следующем входе: сохранённая строка
   `policy_acceptances` под прежней версией перестаёт считаться принятой и заменяется одной
   новой (`/api/me` → `policyAccepted=false`). Это доказано интеграционным тестом.
