## C7. Периметр: скачивание файлов, source maps, allowlist сканера, аудит зависимостей (часть C, 2026-10-16)

Нумерация этого раздела — из нового списка владельца (C1–C4), она не совпадает с C1…C6 выше.

- **C1, скачивание пользовательских файлов.** Каждый ответ с байтом пользователя получает
  `Content-Security-Policy: sandbox; default-src 'none'` (`lib/magic.ts::fileCsp`, вызов в
  `routes/posts.ts::serveFile`): отдельный opaque origin, ни скрипта, ни формы, ни доступа к
  cookie сайта. Единственное исключение — **инлайн-PDF**: `sandbox` запрещает плагины, и с ним
  браузер скачивал бы каждый просмотренный PDF, поэтому для `application/pdf` c
  `?inline` остаётся `default-src 'none'` без sandbox. Белый список инлайна закрывается явно:
  `image/svg+xml`, `text/html`, `application/xhtml+xml`, `text/xml`, `text/javascript` не
  инлайнятся никогда (сегодня такой файл ещё и не загрузить — mime берётся из магических
  байтов, но полагаться на это в двух местах нельзя). Доказательства:
  `test/unit/file-csp.test.ts` (4 теста на правиле) и `test/integration/phase1-uploads.test.ts`
  (3 новых теста читают заголовки реального ответа: PDF-загрузка → sandbox, PDF-инлайн → без
  sandbox, PNG-инлайн → sandbox, SVG → sandbox).
- **C2, source maps.** В CI отдельный шаг после `pnpm -r build`: нет `apps/web/dist` или нет
