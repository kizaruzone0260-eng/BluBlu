## C4. gitleaks в CI — есть, но не в той форме, что просилась

Есть и работает: шаг `gitleaks — независимый скан истории`
([.github/workflows/ci.yml:57-84](file:///C:/Users/Surface%20Book%203/Desktop/BluBlu/.github/workflows/ci.yml#L57-L84)) —
Linux, `fetch-depth: 0`, версия запиннена, **сверка sha256 скачанного бинарника**,
`--redact`, `--log-opts=--all`, падение при `ERR` в выводе (чтобы «чисто» не означало «не
прочитал») и падение при любой находке. Собственный `scripts/security-scan.mjs` идёт двумя
шагами раньше с positive control (`--selftest`).

Не сделано по существу задания:
- **baseline-файла с тремя известными находками нет**: `.gitleaks.toml` — это allowlist по
  **форме значения** (`^ci-…`, `^fictitious-…`), а не список «файл + правило + коммит»;
  CI не терпит ни одной находки, и это осознанно строже, чем baseline;
- **сверки SHA-256 находок со значениями из `cloud.env`/`.env` нет**. Механизм не внесён,
  потому что в текущем прогоне находок ноль: сравнивать нечего, а писать сверку «в стол» —
  значит выдать непроверенный код за сделанный. Если находка появится, порядок такой: снять
  отчёт `gitleaks git --report-path out.json`, посчитать `sha256` от значения каждой находки и
  от каждого значения из `cloud.env`, сравнить множества, наружу печать только
  «совпало N из M, правила …» — значений не печатать никогда.
